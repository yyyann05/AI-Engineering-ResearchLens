# Evaluation Criteria — ResearchLens

## Part B: Define Evaluation Criteria

| Objective / Requirement ID | Evaluation Criterion | Capability Bucket | Measurement Method | Metric | Threshold | User / Business Outcome |
|---|---|---|---|---|---|---|
| **O1 / FR1** | Search Relevance | Domain-specific capability | - Prepare at least 20 search queries on different academic topics.<br><br>- Manually inspect the first 10 retrieved papers for each query and determine whether they are relevant to the query. | Percentage of inspected papers judged relevant to their search queries. | At least 70% of inspected papers are relevant. | Users can find academic papers related to their research topics more efficiently. |
| **O2 / FR2 / FR3 / RAI1** | Metadata Accuracy and Source Transparency | Domain-specific capability | - Inspect 30 retrieved records.<br><br>- Compare displayed metadata with the available OpenAlex records.<br><br>- Check whether available source links and original abstracts are displayed correctly. | Percentage of inspected records with correctly handled metadata and source information. | At least 95% of inspected records are handled correctly, with no invented metadata. All available source links must be displayed, and original abstracts must be shown when available. | Users can check paper details and access original sources to verify information. |
| **FR4 / FR5 / NFR3 / RAI2** | Summary Faithfulness | Generation capability | - Generate summaries for at least 20 available abstracts.<br><br>- Compare each summary with its original abstract using a checklist for unsupported factual claims.<br><br>- Check that each summary is labelled as abstract-based. | - Percentage of summaries without unsupported factual claims.<br><br>- Percentage of summaries correctly labelled as abstract-based. | - At least 90% of reviewed summaries contain no unsupported factual claims.<br><br>- 100% of tested summaries are labelled as abstract-based. | Users can use summaries to understand the main points of papers while being aware of the summaries' limitations. |
| **FR4 / FR5** | Summary Usefulness and Clarity | Generation capability | - Ask intended users to rate sample summaries on a 1–5 scale.<br><br>- Collect ratings for clarity and usefulness. | Average user rating for clarity and usefulness. | Proposed average rating of at least 4.0 out of 5 for both clarity and usefulness. | Users can decide which papers are worth reading in more detail. |
| **O1 / NFR1** | Search Response Time | Cost and latency | - Run at least 20 search queries.<br><br>- Record end-to-end search response times.<br><br>- Exclude unusual external API outages from the normal performance measurement. | 90th-percentile (p90) search response time. | p90 response time ≤ 5 seconds. | Users can search for academic papers without excessive waiting. |
| **FR6 / NFR2 / RAI3** | Error Handling and Missing Abstracts | Instruction-following capability | - Test empty search results, API errors, missing abstracts, and summarisation failures.<br><br>- Check whether the system displays appropriate messages or uses the extractive fallback where applicable.<br><br>- Verify that missing abstracts do not produce fabricated summaries. | - Percentage of tested error cases handled without an unhandled crash.<br><br>- Percentage of missing-abstract cases handled clearly without fabricated abstracts or summaries. | - At least 95% of tested error cases are handled without an unhandled crash.<br><br>- 100% of tested missing-abstract cases are handled clearly without fabricated abstracts or summaries. | Users receive clear feedback when information is unavailable or a system function fails. |
