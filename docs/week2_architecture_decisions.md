# Architecture Decisions — ResearchLens

## Part C: Architecture Decision Records (ADR)

| Decision | Requirement / Constraint | Alternatives Considered | Selected Option | Trade-off Accepted |
|---|---|---|---|---|
| **ADR1: Use one academic data source for V1** | FR1 and FR2 require paper search and filtering. The project needs a manageable initial scope. | - Use OpenAlex only.<br><br>- Integrate OpenAlex, Semantic Scholar, and arXiv from the beginning. | Use OpenAlex as the primary and only runtime academic data source in V1. | - Simpler integration and testing.<br><br>- Search coverage and available metadata depend on OpenAlex. Some records may not contain abstracts. |
| **ADR2: Summarise abstracts rather than full papers** | FR4 and FR5 require concise summaries and display of the original abstract when available. Full text may not be available for every record. | - Summarise available abstracts.<br><br>- Retrieve and summarise full-text papers. | Generate summaries only from available abstracts. | - Keeps the project within a manageable scope.<br><br>- Summaries cannot represent details that appear only in the full paper. The original abstract and source link remain available for further reading. |
| **ADR3: Handle missing abstracts explicitly** | FR6 and RAI3 require clear handling of missing abstracts and prohibit fabricated abstracts or summaries from unavailable text. | - Display a clear missing-abstract message.<br><br>- Attempt to generate a summary without source text. | Display a missing-abstract message and do not generate a summary when no abstract is available. | - Some search results will not have summaries.<br><br>- This avoids presenting invented content as if it came from a paper. |
| **ADR4: Use a local summarisation model with a fallback** | FR4 requires abstract summarisation, while FR6 requires appropriate handling of summarisation failures. | - Use a local pretrained summarisation model.<br><br>- Use an extractive Python fallback. | Use a local pretrained model, with an extractive Python fallback if the model is unavailable or fails. | - Local inference may require more computing resources and may be slower on limited hardware.<br><br>- The fallback may produce less fluent summaries than the pretrained model. |
| **ADR5: Show the summary with the original abstract and source link** | FR3, FR5, and RAI1 require available metadata and traceable source information. | - Show only the generated summary.<br><br>- Show the summary with the original abstract and source link when available. | Display the summary alongside the original abstract and source link when available. | - The results page may contain more text.<br><br>- Users can compare the summary with the original source and decide whether to read the paper. |
| **ADR6: Use a simple web interface for V1** | FR1–FR6 require an interface for searching, filtering, viewing records, and handling errors. | - Build a Python-based web interface.<br><br>- Build a separate frontend and backend. | Use a Streamlit interface connected to the search and summarisation functions. | - Supports a straightforward Python prototype.<br><br>- Offers less flexibility for complex interface customisation than a separately developed frontend. |
